# YouTubePipeline — рабочие правила

## Что это

`Studio_Full_Handoff_2026-08-31/` — **запечатанный пакет передачи**, а не рабочий репозиторий.
Это документация + read-only снимки production-кода трёх сервисов, подготовленные, чтобы
спроектировать их замену. Целостность подтверждается `SHA256SUMS`.

Домен: конвейер `источник → текст → озвучка → визуалы → рендер → обложка → загрузка на YouTube → проверка публикации`.

Четыре слоя:
| Слой | Где | Что делает |
|---|---|---|
| VSGen (web VideoStudio) | `source/vsgen_server/` | проекты, очередь, publication plane, remote render |
| Rewrite Studio (web) | `source/rewrite/` | генерация и мультиязычный рерайт текстов |
| Cover Studio (web) | `source/cover/` | анализ и генерация обложек |
| Desktop VideoStudio | `source/desktop/` | Windows/Tkinter, локальные воркеры, upload-агент |

«Три веба» — это VSGen + Rewrite + Cover. Каждый живёт на своём systemd-сервисе за Caddy,
со своей SQLite, своим auth и своей очередью. Объединение их — это и есть цель переписывания.

## Жёсткие правила

1. **Ничего внутри `Studio_Full_Handoff_2026-08-31/` не редактировать, не переименовывать,
   не удалять и не «чистить».** Любая правка ломает `SHA256SUMS` и обесценивает пакет как
   доказательство фактического поведения production. Новый код пишется в отдельный каталог
   вне архива.
2. **После любой работы рядом с архивом:** `python3 Studio_Full_Handoff_2026-08-31/tools/package_check.py`
   должен печатать `OK`. Если нет — что-то попало внутрь архива.
3. **Код в архиве — свидетельство, а не спецификация.** Он может содержать исторический баг.
   Сохранять надо контракты из `docs/06`, а не структуру файлов.
4. **Не додумывать.** Открытые вопросы уже собраны в `docs/14_KNOWN_GAPS_AND_QUESTIONS.md` —
   15 решений владельца там ещё не приняты. Если ответ нужен для работы, спросить, а не выбрать
   за владельца и не выкинуть требование из scope.
5. **Секретов в архиве нет и быть не должно.** Ключи, токены, cookies, production-БД, профили
   AdsPower сюда не кладутся никогда.

## Экономия контекста (главное)

В `source/` ~206 000 строк Python. Читать их подряд бессмысленно и дорого.

- **Сначала документация, потом код.** Все `docs/*.md` вместе — 2 400 строк, они дают 90%
  понимания. Монолиты объясняют детали, но не намерение.
- **Маршрутизация вопросов — таблица ниже. Не искать grep'ом по всему `source/`.**
- **Никогда не открывать целиком:** `vsgen_server/main.py` (16 965 строк),
  `desktop/src/googler_worker.py` (13 545), `desktop/src/semantic_montage/production_stages.py`
  (13 301), `desktop/src/app_main.py` (11 777), `rewrite/rewrite_core.py` (9 930),
  `rewrite/static/index.html` и `cover/static/index.html` (по ~170 КБ inline UI).
  Работать через `grep -n` + `sed -n 'A,Bp'` по найденным строкам.
- **Один домен на одного агента.** Давать субагенту один сервис + связанные docs/tests,
  а не весь архив. Требовать привязку каждого вывода к файлу и строке.
- **Контракты дешевле кода:** `contracts/openapi/*.json` и `contracts/schema/*.sql` отвечают
  на вопросы про API и таблицы без чтения реализации.

## Ловушки этого проекта

- **Дубли desktop ↔ server.** 14 модулей существуют в обеих копиях. 12 из них байт-в-байт
  идентичны; расходятся только `render_worker.py` (6117 desktop / 5724 server) и
  `tts_worker.py` (744 / 786). Это не мусор — это два разных снимка. Не «дедуплицировать»
  внутри архива; в новой системе это кандидат на общий пакет воркеров.
- **Source drift.** Production, локальный git, Windows build-машина и render-нода содержат
  разные версии одноимённых файлов. Содержимое последнего EXE и версия воркера на render-ноде
  **не подтверждены**. Не утверждать обратное.
- **Скрытая связь сервисов.** `pub_neighbors.py` читает чужие SQLite напрямую и джойнит
  пользователей по логину. Это анти-контракт, переносить нельзя.
- **`done` ≠ опубликовано.** Сейчас publication `done` означает проверенный schedule, а UI
  называет это публикацией.
- **Опасный retry.** Повтор чтения статуса безопасен; повтор оплачиваемого create или отправки
  видео в YouTube создаёт дубль и тратит деньги. Различать всегда.
- **Браузер — часть production.** Selenium без исключения не доказывает результат. Статус
  подтверждается machine-readable данными строки YouTube Studio.

## Git

Репозитория **нет** — ни в корне, ни внутри архива. До первой реальной правки кода нужно
`git init` и первый коммит архива как базовой линии, иначе история изменений не восстановима.
Агенты в `.claude/agents/` рассчитывают на git и на ветку под задачу.

## Агенты

`.claude/agents/` лежит **вне** архива намеренно — иначе `package_check` падает.
`orchestrator.md`, `task-triager.md`, `tech-task.md` перенесены из другого проекта и всё ещё
ссылаются на его репозитории (`backend/`, `ic-client/`, `ic-pizza-mobile/`, `ic-pizza-courier/`,
ветку `eazypay-integration`). Эти ссылки неверны здесь: репо-сет этого проекта — один каталог,
а не четыре. Правила «никогда не гадать» и «не descope молча» из них — верные, их сохранить.

Оркестратор предназначен для реализации задачи по спецификации (triage → план → implementer →
tester → reviewer в изолированных подпроцессах). Для разбора и проектирования он не нужен и
сжигает лимит впустую.
