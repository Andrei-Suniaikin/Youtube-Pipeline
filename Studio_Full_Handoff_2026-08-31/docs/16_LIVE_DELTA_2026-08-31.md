# Live-дельта после базового снимка 29.08

Эта глава отделяет проверенные изменения production от простого изменения данных в БД.
Сверка выполнена read-only 31.08.2026 по active systemd paths, raw SHA, OpenAPI route sets и DDL.

## Матрица свежести

| Контур | Код | OpenAPI | DDL | Что лежит в пакете |
|---|---|---|---|---|
| VSGen | изменены только `main.py` и `src/tts_worker.py` | одна новая description, routes прежние | без изменений | актуальные санитизированные файлы 31.08 |
| Rewrite | raw SHA runtime allowlist совпали | 40 paths без изменений | обе схемы без изменений | безопасный snapshot 29.08, проверенный 31.08 |
| Cover | raw SHA runtime allowlist совпали | 42 paths без изменений | обе схемы без изменений | безопасный snapshot 29.08 + числовой queue config |

Production-DB, WAL/SHM, строки пользователей, проекты, uploads/outputs, логи, cookies,
Codex/Claude homes и provider credentials не копировались.

## Что изменилось в VSGen

- Добавлена отдельная canonical lane `lumean`, не подменяющая legacy `elevenlabs`.
- Web flow отправляет полный текст одним Lumean-заказом с receipt/recovery boundary.
- Для HeyGen до платного create проверяется UUID шаблона и точный `service_key=heygen`.
- Новый результат идёт в `_FINAL_AUDIO_LUMEAN`, legacy output остаётся отдельно.
- Сохранение активной формы как preset и применение настроек к project выполняются атомарно.
- Apply работает fail-closed, а UI/API description отражает этот контракт.
- Сервис был перезапущен после deploy; live health, login и OpenAPI отвечали HTTP 200.

Исходники этих изменений: `source/vsgen_server/main.py` и
`source/vsgen_server/src/tts_worker.py`. Реальные API keys, template/voice UUID и tenant IDs
заменены placeholders.

Санитизированные focused regression tests находятся в
`tests/reference/videostudio/test_server_lumean_route.py` и
`tests/reference/videostudio/test_tts_worker_lumean.py`.

## Скрытая связь аккаунтов между сервисами

`pub_neighbors.py` напрямую читает соседние SQLite-файлы Rewrite и Cover и сопоставляет
аккаунты по case-insensitive login name, а не по общему immutable user ID. Также он читает
Cover preset JSON. `pub_remote.py` ходит к соседним сервисам по loopback, а bearer credentials
хранятся в строках VSGen DB.

Это важный anti-contract текущей системы. В новой версии нужны единая identity model и
versioned service API; прямое чтение чужой БД и join по логину нельзя переносить.

## Runtime и воспроизводимость

- VSGen/Rewrite: Python 3.10.12, общий system site-packages, отдельного lockfile нет.
- Cover: Python 3.10.12, отдельный venv; его пакетный снимок приложен.
- Полные обнаруженные env names без значений: `config/runtime/current_env_names.example`.
- VSGen UI находится inline в `main.py`/`pub_ui.py`; внешних templates/static нет.
- Rewrite и Cover UI находятся в `static/index.html`.
- `source/shared/claude_limits.py` установлен вне каталогов приложений и влияет на cooldown.

Часть optional import-веток Rewrite (`anthropic`, PDF/DOCX/ODF/RTF readers) отсутствует в
active system environment. Их наличие в коде нельзя принимать за воспроизводимый runtime.

## Известная operational drift

31.08 два Rewrite allowlist-ключа в конфигурационном файле отличались от окружения уже
работающего процесса. Значения и user IDs не читались и не передаются. Это означает, что
новая система должна показывать effective config/version, а deploy обязан включать
контролируемый restart и smoke доступа, а не только запись файла на диск.

## Что всё ещё нельзя доказать этим ZIP

- exact содержимое последнего Windows EXE;
- exact версия puller/worker на отдельной render/upload node;
- возможность поднять старый production с нуля из lockfile;
- актуальность внешних cookies, OAuth-сессий и provider quotas;
- восстановление production backup на чистой машине.

Эти пробелы должны стать отдельными discovery/canary задачами до переключения соответствующей
стадии, а не заполняться предположениями.
