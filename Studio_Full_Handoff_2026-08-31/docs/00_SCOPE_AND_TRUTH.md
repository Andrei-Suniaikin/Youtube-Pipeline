# Границы и источники истины

## Что входит в задачу

В систему входят четыре фактических слоя:

1. Desktop VideoStudio для Windows: GUI, локальные проекты и запуск Python-воркеров.
2. Web VideoStudio, или VSGen: многопользовательский кабинет и очередь производства.
3. Rewrite Studio: генерация и мультиязычный рерайт текстов.
4. Cover Studio: анализ и генерация обложек.

Отдельно, но обязательно, входят удалённый рендер, AdsPower, автоматизация YouTube Studio,
контент-план, receipts и проверка фактической публикации.

## Какие снимки считаются фактическими

Серверный allowlist снят напрямую с работающих systemd-сервисов 29.08.2026 и повторно
сверен 31.08. В VSGen два изменившихся runtime-файла (`main.py`, `src/tts_worker.py`)
заменены актуальными санитизированными версиями. Rewrite и Cover сохранили те же raw SHA,
OpenAPI route sets и DDL. Подробная дельта находится в `docs/16_LIVE_DELTA_2026-08-31.md`.

Desktop-слой другой. Исходники в `source/desktop` взяты из текущего рабочего дерева. Они
содержат много незакоммиченных изменений. Сборка Windows создаётся на отдельной машине из
файла с другим именем; эта машина во время подготовки архива была недоступна. Поэтому архив
не утверждает, что локальный `app_main.py` байт-в-байт совпадает с последним EXE.

Версия `render_worker.py` на отдельной рендер-ноде также не была проверена: нода была
недоступна. Это нужно закрыть до первой правки Desktop или render runtime.

## Почему нельзя использовать один git commit

Локальная VideoStudio имеет сотни changed/untracked позиций относительно HEAD. Критические
контракты загрузки и референсов существуют только в текущем working tree. Rewrite и Cover
тоже имеют локальные изменения, но production отличается от них по SHA-256. Поэтому архив
собран явным allowlist и снабжён происхождением каждого файла.

## Что этот архив не доказывает

- что production можно воспроизвести с нуля из одного lockfile;
- что Windows build manifest включает все новые модули;
- что локальные reference tests проходят против production snapshot без адаптации импортов;
- что внешние API сохранят текущие форматы и лимиты;
- что любой конкретный AdsPower-профиль сейчас авторизован в YouTube;
- что все исторические backlog-задачи актуальны.

Архив нужен для понимания и проектирования. Перед изменением конкретного production-файла
разработчик всё равно обязан повторно снять live-срез и diff.
