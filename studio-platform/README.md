# studio-platform

Единый пульт. Новый код и рабочий форк боевого — вне запечатанного архива.

## Запуск

```bash
cd studio-platform
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt   # один раз
.venv/bin/python dev/make_db.py                                          # локальная база
dev/run.sh                                                               # четыре сервиса
.venv/bin/python dev/provision.py                                        # один раз: ключи и пароль
```

| | Адрес | Что это |
|---|---|---|
| Пульт | `127.0.0.1:8010` | новый единый интерфейс |
| Кабинет | `127.0.0.1:8800` | боевой VSGen, 100 путей |
| Rewrite | `127.0.0.1:8899` | 40 путей |
| Cover | `127.0.0.1:8900` | 42 пути |

Ни боевых ключей, ни доступа к VPS не требуется. `VS_SERVER_DISABLE_BACKGROUND=1` глушит
фоновые воркеры, поэтому платных вызовов к провайдерам не происходит.

Вход в кабинет: логин `dev`, пароль из `VS_DEV_PASSWORD` (по умолчанию годится только
локально). В `curl` кабинет не пустит: кука сессии помечена `secure`, и строгие клиенты
не отправляют её по http — браузер на localhost отправляет.

## Правила этого каталога

- **Логику производства не переписываем, а импортируем.** Раскладка ссылок по выходам —
  боевая `pub_tags.add_links()`, порядок фаз — `PHASES` из `pub_engine`, состав этапов —
  `MEDIA_STAGES` из `pub_services`. Копий не делаем: разойдутся.
- **Выпуск создаёт только `materialize()`.** Форма пишет строку в `pub_plan_items`.
  Прямая запись в `pub_releases` ломает `UNIQUE(plan_item_id, version)` и заморозку
  настроек при запуске.
- **`add_links()` всегда с параметром `titles`** — иначе идёт в YouTube за названиями.
- **Интерфейс не врёт.** Нет данных — «не начато». Стадии, которой нет в автоконвейере,
  ставим «не участвует», а не ноль.
- **Каждая правка боевого кода помечается датой, причиной и ссылкой на строку**, где факт
  проверен. Иначе через месяц не отличить исправление от случайной поломки.

## Зашитые пути, которые ломают запуск вне production

Найдены при поднятии кабинета локально. В production невидимы, потому что systemd задаёт
`WorkingDirectory`, а каталоги существуют.

| Что | Где | Обход |
|---|---|---|
| `~/VideoStudio/src` | `server/main.py:121`, `:14047` | изолированный `HOME` → `dev/home` |
| `sessions.db` от рабочего каталога, а не от каталога модуля | `rewrite/auth.py:23` против `server.py:1577` | запуск из каталога сервиса, как в systemd |
| `/data/tenants` без оверрайда | было в `server/main.py` | добавлен `VS_TENANTS_DIR` |

Первые два не исправлены — это поведение боевого кода, чинить его надо отдельным
решением. Третий исправлен в форке тем же способом, каким в файле уже заданы
`VS_SERVER_DB` и `VS_SERVER_KEYS_PATH`; значение по умолчанию прежнее.
