# Studio reader на Минске

`studio_reader.py` — читатель часов, монетизации и доступности функций YouTube Studio,
который вызывается внешним сборщиком `collector.py`.
Рабочий путь: `/home/vova/adspower_audit_20261004/studio_reader.py`.

Исходная production-копия от 4 октября 2026:
`51b0e0dbb3ee5d3ea14061b5afc7f8c19d668f9f5b7a0c46a76f76b6d58ed7b6` (SHA-256).

Два частых вызова скриншота используют CDP `Page.captureScreenshot` с
`fromSurface: true`. Это убирает активацию окна командой WebDriver screenshot.
Первоначальное открытие профиля AdsPower и отдельные переходы внешнего collector
всё ещё могут активировать окно. Правка убирает активацию при снимках, а не все
возможные источники смены фокуса на рабочем столе.
Способ навигации, проверки владельца/брони и чтение данных сохранены.

Проверка из корня репозитория, только стандартная библиотека, без живых браузеров:

```sh
python3 -m unittest discover -s studio-platform/tests -p test_earn_reader_screenshots.py -v
```

Деплой выполняется отдельно, только для `studio_reader.py`:

1. Дождаться отсутствия работающего `collector.py` и заблокировать новые задания
   на время замены. Не заменять модуль во время сбора.
2. Проверить SHA-256 рабочего файла: он должен совпадать с проверенной базой выше
   (при последующих обновлениях — с последним подтверждённым деплоем). При расхождении
   остановиться и сверить изменения; не затирать чужой код.
3. Сделать `cp -p` рабочего файла в резервную копию с уникальным временем в имени.
   Загрузить новый файл во временный файл в том же каталоге, проверить его SHA-256
   против Git-копии и компиляцию Python.
4. Повторно проверить исходный SHA-256 и отсутствие сборщика, затем выполнить
   атомарную замену через `os.replace`. Сохранить SHA-256 новой версии в отчёте.
5. Проверить один штатный сбор: полный результат, скриншоты и сохранение фокуса.
   При откате так же дождаться отсутствия сборщика и атомарно вернуть резервную копию.

Рабочий `earn_puller.py` отличается от снимка в этом репозитории.
**Не разворачивать `earn_puller.py` из репозитория вместе с reader**.

## Защита фокуса Xfwm4 на Минске

15.10.2026 для рабочего стола AdsPower применены `/general/focus_new=false` и
`/general/prevent_focus_stealing=true`. Обычный браузер с окном и CDP-снимки PNG
сохранены. Значения подтверждены чтением и сохранённым XML; PID Xfwm4 и Xvfb
не изменились. Новое тестовое окно `xmessage` не перехватило фокус.

Первые попытки на свободных профилях 26 и 19 остановились до открытия браузера:
AdsPower вернул `Check Proxy Fail`. Следующий обход профиля 20 завершился:
пять каналов, четыре полных результата и один частичный; 13 из 15 разделов
прочитаны полностью. Получены 20 непустых PNG размером 1590×903, выполнены
84 снимка для пробуждения рендера; ошибок скриншотов нет.

При запуске профиля 20 окно перехватило фокус у работающего профиля 31.
После активации нейтрального окна профиль 20 не возвращал себе фокус в течение
наблюдаемых 2 минут 29 секунд. Отдельный перехват при запуске другого профиля 32
учтён отдельно. Полное отсутствие переключений не достигнуто.

У Ostatnia Kryjówka ранее полный lifetime стал частичным: числовые значения
не разобраны из подсказок формата `184.609` / `40.303,3`; прежний частичный Earn
сохранился. В новых снимках lifetime и Earn появился `Verify it's you`, которого
не было в прежних уликах. Связь этих изменений с Xfwm4 не установлена; повтор
не считается проверкой без регрессий. Частичный результат поиска каналов остался
прежним. После проверки профиль 20 закрыт на обеих машинах, бронь освобождена.

Команды `xfconf-query` выполнять в окружении **живого процесса `xfwm4`**:
взять `DBUS_SESSION_BUS_ADDRESS`, `DISPLAY`, `XAUTHORITY`, `XDG_CONFIG_HOME`
из `/proc/<PID xfwm4>/environ`. Для этой сессии `DISPLAY=:99`,
`XDG_CONFIG_HOME=/home/vova/.config/adspower-desktop`. Произвольная D-Bus-шина
SSH-сессии или новый `dbus-run-session` не подходят. После переноса и проверки
этих четырёх переменных:

```sh
cp -p "$XDG_CONFIG_HOME/xfce4/xfconf/xfce-perchannel-xml/xfwm4.xml" \
  "$XDG_CONFIG_HOME/xfce4/xfconf/xfce-perchannel-xml/xfwm4.xml.bak.$(date -u +%Y%m%dT%H%M%SZ)"
xfconf-query -c xfwm4 -p /general/focus_new -s false
xfconf-query -c xfwm4 -p /general/prevent_focus_stealing -s true
xfconf-query -c xfwm4 -p /general/focus_new
xfconf-query -c xfwm4 -p /general/prevent_focus_stealing
```

XML сохраняет `xfconfd`; вручную его не перезаписывать и службы не перезапускать.
Откат прежних значений через ту же живую шину:

```sh
xfconf-query -c xfwm4 -p /general/focus_new -s true
xfconf-query -c xfwm4 -p /general/prevent_focus_stealing -s false
```

Новое окно теперь требует клика для ввода. Явная активация приложением всё ещё
может пройти: эти настройки не обеспечивают полную изоляцию фокуса.
