# Тестовый ролик на своей машине

Цель — получить mp4, который можно скачать и посмотреть. Без заливки на YouTube
и без выкатки куда бы то ни было: всё происходит на этом компьютере.

Путь: **текст → озвучка → кадры → сборка**. Обложка, клипы и заливка для mp4 не нужны
и в этот прогон не входят.

---

## Главное, что стоит знать заранее

**Платформа не рендерит.** Её планировщик берёт из очереди все виды работ, кроме
`render` (`main.py:10768`): ролик собирает отдельная машина, которая сама стучится
в `/api/render/claim`. В бою это минский бокс. Локально его роль играет
`dev/render-node.sh` — второе окно терминала.

Без него конвейер доходит до «Сборки» и молча встаёт. Это единственная поломка,
которую не видно ни по ключам, ни по логам кабинета, поэтому проверять её лучше
до того, как потрачены деньги на кадры.

---

## Шаг 0. Проверка сборки — без единого ключа

Ключей не нужно, денег не тратится, интернета не нужно. Кадры и звук рисует ffmpeg,
а дальше всё настоящее: задача встаёт в очередь, нода её забирает, **боевой**
`render_worker` (тот самый, что крутится в Минске) собирает mp4 и отдаёт обратно.

```bash
.venv/bin/pip install -r requirements-dev.txt      # один раз
brew install ffmpeg                                # если ещё нет

dev/run.sh                                          # окно 1
dev/render-node.sh                                  # окно 2
.venv/bin/python dev/smoke_render.py                # окно 3
```

Через минуту нода скажет `✅ отдан`, и ролик будет здесь:

* на диске — `dev/data/tenants/dev/projects/smoke-*/render/<номер>.mp4`
* в пульте — **Проекты → «Проверка сборки …» → Сборка → скачать**

Если это работает, дальше остаётся только настоящее содержимое.

## Шаг 1. Ключи: что действительно нужно

| Этап | Чем делается | Ключ |
|---|---|---|
| Текст | вставить свой | **не нужен** |
| Озвучка | Edge (движок по умолчанию) | **не нужен**, пакет `edge-tts` |
| Промпты к кадрам | один из четырёх каналов (ниже) | **нужен** один из них |
| Кадры | FastGen | **нужен** `googler` |
| Сборка | ffmpeg на этой машине | не нужен |
| Обложка | Cover Studio | для mp4 не нужна |
| Клипы | Veo | не нужны: в автовыпусках их нет |
| Заливка | минская машина | не в этом прогоне |

**Минимум — два ключа:** `googler` и `openai`. Файл `~/video_studio_api_keys.json`
(путь меняется переменной `VS_SERVER_KEYS_PATH`):

```json
{
  "googler": "ключ FastGen",
  "openai":  "ключ OpenAI"
}
```

Ключ картинок заменить нечем: кадры рисует FastGen, и других маршрутов к ним нет.
А вот промпты к кадрам умеют писать четыре разных канала — ключ OpenAI лишь один из них.

### Чем писать промпты, если ключа OpenAI нет

Канал выбирается в кабинете: **Мои ключи → Чем писать промпты**
(`PROMPT_PROVIDERS`, `server/main.py:758`).

| Канал | Что нужно | Чего стоит |
|---|---|---|
| GPT API | ключ `openai` | предоплаченные кредиты; бесплатного тарифа у API нет |
| Codex токен | CLI `codex`, авторизованный (`codex login`) | подписка ChatGPT Plus/Pro |
| Claude токен | `pip install claude-code-sdk anyio` + `claude setup-token` | подписка Claude |
| Альтернативный Claude API | адрес, ключ и модель — три поля рядом | зависит от провайдера |

Последняя строка — не только про Claude: это **обычный OpenAI-совместимый клиент**
(`googler_worker.py:2483`, `_alt_llm_call`). Он берёт адрес из поля, дописывает
`/chat/completions`, шлёт `Authorization: Bearer <ключ>` и подменяет модель на ту,
что указана. Туда подходит любой сервис с OpenAI-совместимым API — включая бесплатный
тариф Google:

```
адрес:  https://generativelanguage.googleapis.com/v1beta/openai
ключ:   ключ из Google AI Studio
модель: gemini-2.5-flash
```

Канал умеет работать с моделями, которые игнорируют `response_format`: схема дублируется
текстовой директивой, а из ответа достаётся первый JSON-объект. Так что несовпадение
диалекта structured output его не ломает.

**Чего ждать от бесплатного тарифа.** Он ограничен запросами в минуту и в сутки, а ролик
на 155 кадров делает сотни вызовов и шлёт их пачками. Два предупреждения:

- поставь **потоки промптов = 1–2** в «Мои ключи», иначе лимит запросов в минуту
  выбирается мгновенно;
- текст ответа Google при исчерпании квоты — `exceeded your current quota` — совпадает
  с признаком «кончились деньги» (`_LLM_EXHAUSTED_PATTERNS`, `googler_worker.py:288`).
  Воркер считает это фатальным со второго раза и останавливает прогон, а не ждёт. Для
  тестового ролика на пять абзацев это не мешает, для боевого потока — не годится.

Бесплатный тариф Google обучает модели на отправленных данных. Для проверки конвейера
это нормально, для чужих текстов заказчика — решение владельца.

Ключи наружу не показываются нигде — ни на экране, ни в логах, ни в списке процессов:
они уходят воркеру окружением, а не аргументами командной строки.

## Про ffmpeg на маке

Боевой рендерер в девяти местах передаёт ffmpeg ключ `-vsync`. В ffmpeg 8 его выбросили,
оставив `-fps_mode`. На Минске стоит ffmpeg 6 и всё работает; homebrew ставит 9-й.

Ломается это скверно: падает **каждая** пачка картинок, рендерер считает отказ
восстановимым, подставляет чёрный фон и рапортует об успехе. На выходе ролик правильной
длины, со звуком, со статусом «готово» — и без единой картинки. Ни в очереди, ни в
карточке проекта об этом ни слова.

`dev/render-node.sh` разбирает версию ffmpeg сам и на 8+ подставляет прослойку
`dev/ffmpeg-compat/`, которая переписывает ключ. Движок при этом остаётся побайтово
минским. В строке запуска ноды видно, включилась ли она:

    ffmpeg     /opt/homebrew/bin/ffmpeg (v9, через прослойку -vsync→-fps_mode)

## Шаг 1а. Самый дешёвый настоящий ролик

Текст для первого прогона лежит готовым: `dev/образец_текста.txt` — двенадцать
предложений про рассвет в горах. Выбран не случайно: в нём нет людей, брендов и ничего
такого, на чём модель картинок упирается в модерацию, а «утро в горах» рисуется одинаково
хорошо любой моделью. Речи в нём примерно на минуту.

Сколько кадров получится — считает поле **«Предложений на картинку»**
(`--sentences_per_prompt`, по умолчанию `3`):

| Предложений на картинку | Кадров из этого текста |
|---|---|
| 3 (по умолчанию) | 4 |
| 4 | 3 |

Настройки проекта для самого дешёвого прогона:

| Поле | Значение | Почему |
|---|---|---|
| Предложений на картинку | `4` | три кадра — уже полноценный ролик |
| Модель картинок | `OPENAI` (по умолчанию) | 1 кредит FastGen за кадр; это маршрут FastGen, а **не** прямой OpenAI |
| Качество | `720p` | быстрее собирается, меньше файл |
| Переходы | нет | |
| Синхрон по озвучке | выкл | тянет whisper, которого на маке нет |
| Клипы, обложка, заливка | не трогать | к mp4 отношения не имеют |
| Голос | Edge, русский | бесплатно |

Итого расход: **три кредита FastGen** и десяток вызовов канала промптов. Ролик — около
минуты, 720p. Если он собрался и скачался, конвейер рабочий целиком, и дальше длина текста
меняет только счёт, но не маршрут.

## Шаг 2. Запуск

```bash
dev/run-live.sh          # окно 1 — платформа с включённым планировщиком
dev/render-node.sh       # окно 2 — сборка ролика
```

`dev/run-live.sh` отличается от `dev/run.sh` ровно одним: планировщик включён и задачи
из очереди действительно берутся. Скрипт сам проверит файл ключей и `ffmpeg` и откажется
стартовать, если чего-то нет.

## Шаг 3. Первый ролик — коротким текстом

Ролик на 155 кадров — это 155 платных вызовов. Путь проверяется тем же самым и
на пятнадцати, поэтому первый текст берите абзацев на пять.

1. Кабинет (`http://127.0.0.1:8080/`) → создать проект, вставив свой текст.
2. Озвучка: движок **Edge** — бесплатный, ключа не просит.
3. Кнопка **«Сделать всё видео (озвучка → картинки → видео → рендер)»** — это ровно
   четыре этапа, и все четыре делает сам кабинет. Озвучка и картинки стартуют сразу;
   видео и рендер ставятся отложенно и стартуют сами, когда материалы дозреют.

**Сценарий и обложка в «Сделать всё» не входят.** Их делают соседние сервисы — текст
пишет Rewrite, обложку рисует Cover — и заказываются они своими кнопками: в пульте
(`/studio` → «Проекты») это карточки **«Текст»** и **«Обложка»** в панели «Запуск для
отмеченных», а внутри проекта — вкладки «Сценарий» и «Обложка». В кабинете это
написано строкой под самой кнопкой; в пульте — окном сразу после нажатия, там же
видно, сколько задач поставлено, сколько отложено, сколько пропущено и почему.

В первом прогоне ни то, ни другое не нужно: текст мы вставили руками на шаге 1, а
обложка к mp4 отношения не имеет.

Хочется по шагам — этапы запускаются по одному на странице проекта.

## Шаг 4. На что смотреть, пока идёт

**Выпуски** — полоска по этапам; отрезок закрашивается по мере готовности, при наведении
видно, какой это этап.

**Очередь** — что делается прямо сейчас во всех трёх сервисах.

**Ключи → «Занято прямо сейчас»** — сколько потоков занято из доступных: одинокая задача
берёт весь бюджет ключа, несколько — делят.

**Проекты → карточка** — кадры миниатюрами по мере появления, озвучка плеером, готовый
ролик проигрывателем и кнопкой скачивания. Плюс «Во что обошёлся» — число оплаченных
вызовов по видам работы.

## Если что-то встало

**Очередь дошла до «Сборки» и стоит.** Не запущена нода: `dev/render-node.sh`.
Проверить, что она жива, можно её же логом — она печатает опрос каждые три секунды.

**Выпуск ушёл в разбор.** Откройте его: причина написана словами. Починив причину,
нажмите «Вернуть в работу» — движок продолжит с той фазы, где остановился. Уже
сделанное и оплаченное не переделывается.

**Задача упала.** Значок повтора (круговая стрелка, подпись «Повторить» всплывает при
наведении) в очереди и в карточке проекта. Журнал платных
вызовов не даст заплатить второй раз за то, что уже заказано: если заказ был создан,
повтор подхватит его, а не создаст новый.

**Провайдер отвечает 429.** Ключ уйдёт отдыхать сам, это видно на экране «Ключи».
Задачи дождутся пробуждения.

## Чего в этом прогоне не будет

**Заливки на YouTube** — нужна минская машина с профилями AdsPower. Проверяется отдельно,
на тестовом канале.

**Проверки, что ролик вышел** — нужен ключ YouTube Data API и опубликованный ролик.

**Клипов** — автоконвейер их не ставит (решение от 04.09: в ТЗ их нет). Ролик собирается
из кадров.

**Синхронизации кадров по озвучке** — она тянет whisper, которого на маке нет. На боевой
ноде он есть; локально этот переключатель лучше держать выключенным.
