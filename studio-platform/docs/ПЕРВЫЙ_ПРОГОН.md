# Первый настоящий прогон

Проверяем весь путь на настоящих провайдерах: ссылка → текст → озвучка → кадры →
рендер → обложка. Заливка не пойдёт — ей нужна минская машина с профилями AdsPower.

## 1. Ключи

Файл `~/video_studio_api_keys.json` (путь меняется переменной `VS_SERVER_KEYS_PATH`):

```json
{
  "googler": "ключ картинок и клипов",
  "openai": "ключ OpenAI",
  "elevenlabs": "ключ озвучки",
  "veo": "ключ VeoNonStop"
}
```

Нужны не все: без `veo` не будет клипов, без `elevenlabs` — озвучки. Кадры и текст
пойдут и на двух первых.

Ключи наружу не показываются нигде — ни на экране, ни в логах, ни в списке процессов:
они уходят воркеру окружением, а не аргументами командной строки.

## 2. Запуск

```bash
cd ~/Documents/YouTubePipeline/studio-platform
dev/run-live.sh
```

Отличие от `dev/run.sh` ровно одно: включён планировщик. Без него задачи стоят
в очереди и их никто не берёт — так и задумано, когда разбирают интерфейс.

Скрипт сам проверит, что файл ключей на месте и `ffmpeg` отвечает, и откажется
стартовать, если нет.

## 3. Первый ролик — коротким текстом

Ролик на 155 кадров — это 155 платных вызовов картинок плюс озвучка плюс обложка.
Путь проверяется тем же самым и на пятнадцати.

Как ограничить: **Текст → Вставленный текст**, положить абзацев пять. Число кадров
считается по сценам, а сцены по тексту — короткий текст даёт короткий ролик.

Дальше: **Выпуски → Новый выпуск по ссылке** для полного пути, либо запускать этапы
по одному через **Проекты**, если хочется смотреть по шагам.

## 4. На что смотреть

**Выпуски** — полоска по этапам. Отрезки закрашиваются по мере готовности; при
наведении видно, какой это этап и что с ним.

**Очередь** — что сейчас делается во всех трёх сервисах.

**Ключи → «Занято прямо сейчас»** — сколько потоков занято из доступных. Здесь видно
главное изменение: одинокая задача берёт весь бюджет ключа, несколько — делят.

**Проекты → карточка** — кадры миниатюрами по мере появления, озвучка плеером,
готовый ролик проигрывателем. Плюс «Во что обошёлся»: сколько оплаченных вызовов.

**Админ** — тревоги и место на диске.

## 5. Если что-то встало

**Выпуск ушёл в разбор.** Откройте его: причина написана словами. Починив причину,
нажмите «Вернуть в работу» — движок продолжит с той фазы, где остановился, а не
с начала. Уже сделанное и оплаченное не переделывается.

**Задача упала.** В очереди и в карточке проекта у неё кнопка «Повторить». Журнал
платных вызовов не даст заплатить второй раз за то, что уже заказано: если заказ
был создан, повтор подхватит его, а не создаст новый.

**Провайдер отвечает 429.** Ключ уйдёт отдыхать сам, это видно на экране «Ключи».
Задачи дождутся пробуждения.

## 6. Сколько это стоит

Считается по журналу платных вызовов: **Проекты → карточка → «Во что обошёлся»**.
Там число оплаченных вызовов по видам работы — то же число, которое будет выброшено,
если проект убрать с диска.

## Чего в этом прогоне не будет

**Заливки на YouTube** — нужна минская машина. Проверяется отдельно, на тестовом канале.

**Проверки, что ролик вышел** — нужен ключ YouTube Data API и опубликованный ролик.

**Клипов** — автоконвейер их не ставит (решение от 04.09: в ТЗ их нет). Ролик собирается
из кадров.
