## Откуда берётся сам дефект — найдено 02.10.2026

Картинки раскладываются по времени **под распознанную речь**. Кадр получает почти нулевую
длительность, когда распознавание теряет фразу — их собственный пример в коде: «Charlotte»
→ «Şarlot».

Но распознавание нужно **не всегда**. Если синтезатор речи вернул метки слов
(`word_metadata_path`), раскладка берёт их и не угадывает ничего. Замер по всем 101
проекту на машине:

| Чем озвучено | С метками слов | Без меток |
|---|---|---|
| Edge | **6** | 0 |
| FastGen | 0 | **16** |
| Lumean | 0 | **79** |

Корреляция без единого исключения: **Edge метки отдаёт, Lumean и FastGen — нет.** Там, где
меток нет, раскладка вынуждена распознавать речь заново — и иногда теряет фразу.

### ПРОВЕРЕНО 02.10.2026: Lumean метки ОТДАЁТ

Заказчик сказал, что не знает. Проверили сами — спросили у API Lumean уже оплаченный
заказ. В ответе, в поле `result.service_files`, лежит:

```
subtitles.srt   subtitles.vtt   subtitles.lrc   alignment.csv   result.json
```

**`alignment.csv` — это и есть пословная раскладка.** Она делается при каждом заказе и
уже оплачена вместе со звуком.

Почему её не используют: код манхвы (`app/voice_lumean.py:658`) ставит `words_path = ""`
с комментарием «меток слов у Lumean нет». Это утверждение неверно. Скачивается только
`files[0]` — mp3 (`download`, строка 602), а `service_files` не запрашиваются вовсе,
хотя берутся они той же ручкой `/storage/url`, которой уже качается звук.

Из-за этого раскладка вынуждена распознавать речь заново — и теряет фразы.

**Важно:** у Lumean файлы хранятся недолго (у проверенного заказа стоит
`files_expired: true`). Значит скачивать `alignment.csv` надо в тот же момент, что и
mp3 — там, где код уже ходит за ссылкой. Для старых роликов данные уже недоступны.

Про **FastGen** (16 проектов из 95) такой проверки нет: его код про тайминги не
спрашивает вовсе, и что отдаёт его API — мы не смотрели.

### Что это значит для ремонта

**Повтор раскладки на том же звуке почти наверняка даст тот же результат:** распознавание
пойдёт по тому же файлу с теми же настройками. Бесплатно, но бесполезно — разве что
поменять модель распознавания.

Выход один, и он дешёвый: **скачивать `alignment.csv` вместе с mp3 и класть его в
`words_path`.** Данные уже делаются и уже оплачены — их просто не забирают. После этого
раскладка перестаёт угадывать, и дефект исчезает на всех будущих роликах.

Правка на стороне манхвы, в двух местах `app/voice_lumean.py`: в `download` попросить
`service_files` той же ручкой `/storage/url`, и в строке 658 заполнить `words_path`
вместо пустой строки.

Переозвучка старых роликов — самый дорогой путь и помогает только им самим.
