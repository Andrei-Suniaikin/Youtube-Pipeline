# Задача 01 — Экран выпуска и старт по ссылке

**Статус:** черновик на согласование. К реализации не передавать до подтверждения владельца.

## Контекст

Конвейер «ссылка на YouTube → запланированная публикация» в production **уже работает**:
девять фаз в `pub_engine.py`, обработчики шагов в `pub_services.py`, раскладка ссылок по
выходам канала в `pub_tags.add_links()`. Не хватает двух вещей — верхнеуровневого входа
(сейчас ссылки вставляются внутри карточки канала) и экрана, где видно движение выпуска.

Задача даёт конвейеру вход и лицо. Она не меняет ни одного правила производства.

## Что делаем

Три экрана поверх существующих данных, плюс маленькое приложение, которое их отдаёт.

### Экран 1 — список выпусков
Строка на выпуск: канал, заголовок донора, язык, время выхода, текущая фаза, возраст.
Фильтры: канал, фаза, статус. Сортировка по времени выхода.

### Экран 2 — карточка выпуска
Вертикальный степпер из семи стадий (раздел 14 ТЗ). Источник каждой строки:

| Стадия | Откуда берётся |
|---|---|
| Сценарий | `pub_release_jobs` где `service='rewrite'` |
| Озвучка | `service='vsgen' AND kind='tts'` + `queue_tasks` (прогресс, стадия) |
| Кадры | `kind='images'` + `queue_tasks.progress`, `stage` |
| Клипы | `kind='video'` — **в автоконвейере отсутствует**, показываем честно «не участвует» |
| Сборка | `kind='render'`, плюс `kind='chapters'` как необязательный |
| Обложка | `service='cover'` |
| Публикация | `pub_upload_jobs`: `phase`, `verdict`, `video_id`, `host`, `worker` |

Под степпером — лента: `pub_release_events` (переходы фаз) и `pub_release_log` (сообщения).

Строка стадии показывает статус, ключевые факты и ничего не выдумывает: если данных нет,
пишем «нет данных», а не ноль.

### Экран 3 — старт по ссылке
Форма: канал (обязательно), поле ссылок (одна на строку, принимается пачка),
необязательный точный слот. Отправка → `pub_tags.add_links()`.

Результат показывается как есть, тремя списками: разложено по датам, сохранено без даты
(не влезло в горизонт), пропущено как дубль. Это ровно то, что функция возвращает.

## Что НЕ делаем

- Не трогаем движки и `pub_engine`/`pub_services` — ни строки.
- Не пишем в `pub_releases` напрямую. Выпуск рождает только `materialize()`.
- Не переносим Rewrite и Cover, не сливаем базы, не трогаем авторизацию.
- Никаких сетевых вызовов: ни к провайдерам, ни к соседям на 8899/8900, ни к YouTube.
- Не редактируем `Studio_Full_Handoff_2026-08-31/` и `live_2026-09-02/`.

## Где пишем код

```
studio-platform/
  web/
    app.py          новое: FastAPI-приложение, отдаёт UI и read-only JSON
    index.html      новое: единая страница, ванильный JS (как в Rewrite/Cover)
  server/           рабочий форк кабинета — ЧИТАЕМ, импортируем, не меняем в этой задаче
  dev/
    make_db.py      уже готово: локальная база из боевого DDL + фикстуры
```

`web/app.py` — временная оболочка на время разработки. В боевой системе эти же роуты
становятся роутером внутри кабинета; отдельным приложением они живут только чтобы
экраны можно было проверять без ключей, без данных и без соседних сервисов.

## Контракты

Читающие роуты нового приложения:

| Метод | Путь | Отдаёт |
|---|---|---|
| GET | `/` | `index.html` |
| GET | `/ui/releases` | список выпусков с фильтрами `channel`, `phase`, `status` |
| GET | `/ui/releases/{release_id}` | семь стадий + лента событий и лога |
| GET | `/ui/channels` | каналы для выпадающего списка формы |
| POST | `/ui/links` | `channel_id`, `links`, необязательный `slot` → результат `add_links` |

`POST /ui/links` — временный адрес. В боевой системе форма отправляет на существующий
`POST /api/channels/{cid}/links`, у него та же семантика. Различие фиксируем комментарием
в коде, чтобы при переносе не забыть.

## Что переиспользуем, а не пишем заново

Проверено импортом: `pub_tags.py` тянет только stdlib и `channel_slots`, тот — только
stdlib. Всё это работает офлайн.

| Функция | Файл | Зачем |
|---|---|---|
| `add_links()` | `server/pub_tags.py:111` | раскладка ссылок: дубли, горизонт, точный слот |
| `next_free_slot()`, `upcoming_slots()` | `server/channel_slots.py` | ближайший свободный выход |
| `release_steps()`, `release_look()` | `server/pub_ui.py` | цепочка этапов, состояние и цвет |
| `schedule_text()`, `per_day()`, `flag()`, `lang_title()` | `server/pub_ui.py` | расписание и подписи |
| `PHASES`, `PHASE_DEADLINES` | `server/pub_engine.py:39` | порядок и сроки фаз |

`add_links()` вызывать **всегда с параметром `titles`** — иначе она пойдёт в сеть за
названиями доноров. В офлайн-режиме подставляем заглушку.

## Приёмка

1. `python3 dev/make_db.py` создаёт базу: 29 таблиц из боевого DDL, один выпуск в фазе
   `media_ready`, три записи в `pub_release_jobs`, две в `queue_tasks`.
2. Экран выпуска показывает **семь** строк. У «Озвучки» статус готово, у «Кадров» —
   идёт с прогрессом 63% и стадией «38 из 60», у «Клипов» — «не участвует»,
   у «Сборки», «Обложки» и «Публикации» — не начато. Ни одна строка не выдумана.
3. Форма принимает три ссылки, из которых одна дубль: результат — одна разложена по дате,
   одна сохранена без даты, одна пропущена. Числа совпадают с тем, что вернула `add_links`.
4. Ни одного сетевого вызова: прогон под запретом сети проходит целиком.
5. `pub_releases` не изменилась: `SELECT COUNT(*)` до и после работы формы равны.
6. `python3 Studio_Full_Handoff_2026-08-31/tools/package_check.py` печатает `OK`.
7. Страница открывается в одном файле без сборки: ни npm, ни vite, ни внешних скриптов.

## Как проверять

```bash
cd studio-platform
python3 dev/make_db.py
python3 -m uvicorn web.app:app --port 8010
# открыть http://127.0.0.1:8010
```

Проверка «нет сети» — прогон с подменённым сокетом либо просто грепом: в `web/app.py`
и `index.html` не должно быть ни `requests`, ни `httpx`, ни `fetch(` на внешние адреса.

## Риски и запреты

- **Дубль выпуска.** Единственный законный способ создать `pub_releases` — `materialize()`.
  Форма пишет только `pub_plan_items`. Нарушение ломает `UNIQUE(plan_item_id, version)`
  и правило ТЗ §03/№6 о заморозке настроек.
- **Сеть в обработчике.** `donor_title()` ходит в YouTube и под write-замком базы держит
  весь кабинет до шести секунд на ссылку. В production это решено пулом потоков до
  открытия базы; в нашей задаче — просто не зовём.
- **Выдуманные данные на экране.** Если стадии нет в `pub_release_jobs`, показываем
  «не начато», а не нули. Правило ТЗ: интерфейс не врёт.
