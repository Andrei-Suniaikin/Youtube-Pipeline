# Тревоги в телеграм — что нужно сделать

Система будет писать в телеграм, когда конвейер встал: очередь не двигается,
провайдер на паузе, ролики не заливаются, слот прошёл без ролика, кончается диск,
**кончился ключ провайдера — его нужно заменить**. Плюс отдельным сообщением —
когда починилось.

Нужны две строки: токен бота и id чата. Пять минут.

## 1. Завести бота

В телеграме найти **@BotFather** → `/newbot` → ответить на два вопроса
(имя и username, username должен заканчиваться на `bot`).

В ответ придёт строка вида:

```
123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw
```

Это **токен**. Он даёт полный доступ к боту — не пересылать в открытые чаты
и не класть в репозиторий.

## 2. Открыть боту дорогу

Бот не может написать первым — сначала ему надо разрешить. Как именно, зависит от
того, куда должны приходить тревоги.

**Личные сообщения.** Написать боту любое сообщение, например `/start`.

**Группа** (тревоги видят несколько человек). Создать группу, добавить бота и
отправить в неё `/start`. Именно команду: у ботов по умолчанию включён режим
приватности, и обычный текст в группе бот не увидит.

**Канал.** Здесь иначе: боту не пишут, его делают **администратором**.
Канал → «Управление каналом» → «Администраторы» → «Добавить администратора» →
найти бота по его имени → оставить право **«Публикация сообщений»** → сохранить.

> Бот ищется по своему username — тому, что заканчивается на `bot` и был задан при
> создании, а не по отображаемому названию. Если поиск не находит, откройте
> @BotFather → `/mybots`: там список ваших ботов и прямая ссылка на каждого.

## 3. Узнать адрес чата

Открыть в браузере, подставив свой токен:

```
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```

В ответе найти `"chat":{"id":...}`. Личный чат — положительное число, группа и
канал — отрицательное, начинается на `-100`.

**Для публичного канала это можно пропустить.** Вместо числа годится его имя:
`VS_TG_CHAT=@имя_канала`.

Если ответ пустой: значит шаг 2 не сработал — бот не получил ни сообщения, ни прав
администратора. Ещё одна причина: у бота задан webhook, тогда `getUpdates` всегда
пуст; снимается запросом `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`.

## 4. Прописать в окружение

Две переменные там же, где живут остальные настройки сервиса
(`.env` рядом с кодом либо `EnvironmentFile` юнита systemd):

```
VS_TG_TOKEN=123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw
VS_TG_CHAT=-1001234567890
```

Проверка, что связь есть:

```bash
.venv/bin/python dev/alerts.py --test
```

Должно прийти сообщение «Проверка связи». Если не пришло — команда напечатает,
что именно не так.

## Что важно знать

**Ничего не стоит.** Bot API бесплатен. Лимиты — 20 сообщений в минуту в группу;
у нас одиннадцать поводов, каждый не чаще раза в час, потолок около 22 сообщений
в час (повод плюс «починилось» по нему же).

**Про ключ придёт два разных сообщения, и это не дубль.** Сначала, за неделю до
срока, — «Ключ FastGen истекает, действует до такого-то числа»: это просьба успеть.
Когда срок вышел или провайдер перестал ключ принимать — «Ключ googler кончился,
нужен новый»: конвейер уже стоит. Новый ключ ставите вы; система ключи не продлевает
и никогда не проверяет их «пробной генерацией» — она спрашивает у провайдера только
бесплатную статистику. Значение ключа в сообщение не попадает — только маска вида
`fg_l…b3gt`. Когда новый ключ примут, придёт «ПОЧИНИЛОСЬ».

**Пока переменных нет, система работает как раньше** — просто молчит. Тревоги
всё равно определяются и видны на экране «Админ», отметкой «ещё не сказано».

**Токен можно отозвать в любой момент** — @BotFather → `/revoke`. Старый перестаёт
работать сразу.

**Канал удобнее группы, если читателей больше двух.** В канал можно добавлять людей,
не давая им права писать, и история тревог не перемешивается с обсуждением.
