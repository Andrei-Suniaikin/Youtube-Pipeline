# Что сделано и что осталось

Составлено 03.09.2026, обновлено 07.09. Проверено запуском: платформа поднимается
**одним процессом на одном порту**, 11 тестовых файлов проходят, `package_check.py`
печатает `OK`.

```
http://127.0.0.1:8080/          кабинет — весь интерфейс и API, пути прежние
http://127.0.0.1:8080/studio/   пульт — новый единый интерфейс
http://127.0.0.1:8080/rewrite/  Rewrite Studio
http://127.0.0.1:8080/cover/    Cover Studio
```

Один вход открывает всё четыре.

## Утром — десять минут

Два ключа, оба необязательные: без них система работает, просто молчит про аварии
и не подтверждает выход роликов.

### 1. Телеграм-тревоги

1. `@BotFather` → `/newbot` → токен.
2. Написать боту любое сообщение (или добавить его в группу).
3. `cp .env.example .env`, вписать `VS_TG_TOKEN=`.
4. `.venv/bin/python dev/alerts.py --whoami` → покажет `chat_id`, вписать `VS_TG_CHAT=`.
5. `.venv/bin/python dev/alerts.py --test` → должно прийти сообщение.

После этого `dev/run.sh` сам поднимет цикл тревог рядом с сервисами, а на боевой
машине их ставит systemd: `deploy/README.md`.

### Про лимиты Telegram

Bot API бесплатен. Ограничения: около 30 сообщений в секунду
суммарно, не чаще одного в секунду в один чат, и не больше **20 в минуту в групповой
чат** — это и есть та цифра, что попадалась. Наши тревоги: одиннадцать поводов,
каждый не чаще раза в час, плюс «починилось». Потолок — примерно 22 сообщения в час.
В лимиты мы не упираемся даже близко.

### 2. Ключ YouTube Data API — подтверждение, что ролик вышел

`console.cloud.google.com` → APIs → YouTube Data API v3 → Credentials → API key, затем:

```bash
.venv/bin/python dev/verify_public.py --save-key AIza...
.venv/bin/python dev/verify_public.py --run
```

Квота бесплатная и с тысячекратным запасом: `videos.list` стоит 1 единицу из 10 000
в сутки. Ключ видит только публичные ролики — этого хватает, чтобы подтвердить выход,
и не хватает, чтобы отличить «ещё приватный» от «удалён» (C5).

### 3. Вход в пульт

Логин и пароль — те же, что в кабинете. Своей учётной записи у пульта нет.

## Осталось

### A. Не блокировано

Всё, кроме A6-рерайта и A2-прав, сделано вторым проходом.

| № | Задача | Состояние |
|---|---|---|
| A1 | Тревоги на systemd-таймере | готово, `deploy/studio-alerts.{service,timer}` |
| A2 | Вход в пульт | готово; **разделение прав — нет**, см. ниже |
| A3 | Отмена и повтор в строке очереди | готово, пересылкой в тот сервис, чья задача |
| A4 | Форма нового выпуска | готово как предпросмотр, не как выбор — см. ниже |
| A5 | Повтор одного этапа выпуска | готово, кнопка привязана к задаче этапа |
| A6 | Клипы и рерайт в журнале | **готово полностью** 04.09 |
| A7 | Поздняя проверка выхода | готово, `server/pub_verify.py` |

Три уточнения, где сделано не то, что было записано, и почему.

**A2, права.** Вход сделан, разделения ролей нет и не будет здесь: роль живёт в
`users.role` кабинета, а кто хозяин личности после объединения — это C1. Пульт
проверяет сессию кабинета и на этом останавливается сознательно.

**A4, выбор пресета.** Селектора нет намеренно. Пресеты берутся из канала, а колонка
`pub_plan_items.overrides` в схеме есть, но за неё во всём кабинете не держится ни одна
строка кода. Селектор поверх мёртвой колонки — ровно та настройка, которую ТЗ требует
убрать. Вместо выбора сделан предпросмотр: чем именно будет сделан ролик, на какие
выходы встанут ссылки и существуют ли эти пресеты вообще.

**A6, рерайт — сделан 04.09, но иначе, чем задумывалось.** Единицей стал не кусок
текста, а пара (выпуск, язык): именно за неё платит кабинет одной задачей рерайта.
Внутри задачи Rewrite сам не переплачивает — у него есть пофрагментное продолжение.
А между запусками защиты не было: тот же текст, тот же пресет, новая задача — и оплата
заново. Протокол между сервисами менять не потребовалось: заявка живёт в кабинете,
там же, где принимается решение платить.

### B. Честные долги журнала платных вызовов

| № | Долг | Почему не закрыт |
|---|---|---|
| B1 | У синхронных провайдеров нет идентификатора заказа | окно между отправкой и ответом не закрыть без idempotency key на их стороне — нужно спросить провайдеров |
| B2 | `cost` всегда пуст | провайдеры не возвращают подтверждённую цену; сумма по проекту пока не считается |
| B3 | В параллельном режиме по URL `result_path` пуст | путь становится известен позже записи |
| B4 | В Cover `delivered()` срабатывает до записи на диск | «готово» доказывается файлом — здесь пока доказывается ответом |
| ~~B5~~ | ~~Рерайт вне журнала~~ | закрыт 04.09 |

B3 в клипах закрыт по дороге: результат сохраняется там же, где закрывается строка.
Ошибку нашёл тест до коммита — успешный клип записывался как неудача, и следующий
прогон оплатил бы его заново.

### C. Блокировано решением владельца

| № | Задача | Чего ждём |
|---|---|---|
| C1 | ~~Слияние Cover~~ | **решено 04.09**: один процесс, единый вход |
| C2 | ~~Слияние Rewrite~~ | **решено 04.09**: то же |
| ~~C3~~ | ~~Убрать `pub_neighbors.py`~~ | **закрыт 04.09**, перепроверено 07.09 — см. ниже |
| C4 | Включить уборку диска | **сроки хранения**: через сколько дней после публикации чистить промежуточное и через сколько удалять проект |
| C5 | Отличать «ещё не вышел» от «удалён» | **OAuth-токен канала**: ключа API для этого не хватает — он видит только публичное |
| C6 | Разделение прав в пульте | то же, что C1: где живут роли |
| C7 | Редактор полей пресета в пульте | нужен ли он вообще: у обложек их больше двадцати, и правка есть в самом сервисе |

C1 и C2 закрыты 04.09. Хозяином личности стал кабинет: `tenant_id` — общий
идентификатор во всех трёх сервисах, пароль проверяется в одном месте, соседи узнают
человека по сессии кабинета. Свой вход у них остаётся рабочим при раздельном запуске.

**C3 закрыт, и решение оказалось третьим.** Записано было так: раз ключ принадлежит
одному человеку, для пресетов чужого тенанта нужен либо ключ на каждого, либо
привилегированный эндпоинт. Ни то ни другое не понадобилось. Сервисы живут в одном
процессе, поэтому сосед спрашивается своей же функцией с явным `user_id`
(`pub_neighbors._rewrite_preset_map` → `server._api_presets`). Ключ не используется
сознательно: он отдал бы пресеты СВОЕГО владельца, и карточка канала партнёра
показывала бы чужое — молча и правдоподобно. Новой двери наружу не появилось:
привилегия существует только внутри процесса.

C4 не требует кода — механизм готов и ждёт двух чисел.

|---|---|
| 1 · Каналы главной | канал — стартовый экран; две вкладки «Ролики» и «Настройки»; постановка ссылок на вкладке роликов |
| 2 · Топбар | Каналы · Проекты · Очередь · Пресеты · Ключи · Профиль. Выпуски, Текст, Обложки и Админ переехали внутрь разделов |
| 3 · Календарь | месяцы сеткой, справа сверху в дне — число вышедших роликов; пропуск — красной рамкой |
| 4 · Общий пресет | пятая группа «Текст и обложка»: один пресет накрывает озвучку, картинки, клипы, сборку и обложку |
| 5 · Вкладки проекта | Обзор · Текст · Озвучка · Кадры · Клипы · Сборка · Обложка · Настройки |
| 6 · «invalid schema» | починено: `VS_SUBS_PROXIES=direct` и человеческий отказ вместо `InvalidSchema` |
| 7 · Ключи в профиль | профиль с учётными записями, ролью, ключами и состоянием системы |
| 8 · Ресурс ключа | восьмой повод тревоги: отказ, который означает деньги, а не частоту |

Отдельно приведены к ТЗ пресеты: убраны источник Bing, теги, «Авто-герой», случайный и
алфавитный порядок материалов, раздел «Голоса»; починены порядок движков озвучки,
гашение мин/макс при синхроне и показ настроек только у поддерживающих провайдеров.
